# V4 接入正式流程前检查清单

## 1. 当前 V4 已具备能力

- Product Schema：用于描述产品结构和不同产品类型的字段。
- Example Order：用于保存真实或接近真实的订单样例。
- Renderer：用于把结构化订单转换成可渲染字段。
- Excel Render Rules：用于描述字段如何写入 Excel。
- Rule Preview：用于预览规则执行前的写入动作。
- Rule Executor：用于把规则执行到调试 Excel 文件。
- Template Rule Executor：用于把规则执行到真实 Excel 模板副本。
- V4 健康检查接口：`GET /api/v4/health`，用于确认 Schema、Example、Excel Rules 是否可读取。

## 2. 暂不接入首页的原因

- V3 主流程已经稳定，不能直接替换。
- V4 当前仍是实验链路，适合先独立验证。
- 需要更多真实订单验证，避免只适配少数样例。
- 需要确认不同产品类型之间的字段差异。
- 需要确认 V4 失败时不会影响 V3 生成方式。

## 3. 接入首页前必须满足的条件

- Schema 稳定，主要产品类型结构已经明确。
- Example 覆盖主要产品类型。
- Excel Rules 能覆盖真实模板。
- Rule Executor 能稳定写入真实模板副本。
- 失败时能回退到 V3 生成方式。
- V4 输出结果能和 V3 输出结果并行对比。
- 用户确认 V4 结果符合实际业务习惯。

## 4. 建议接入策略

- 第一阶段：继续保留 `/v4-schema` 独立验证。
- 第二阶段：首页增加“使用 V4 渲染预览”按钮，但不影响正式生成。
- 第三阶段：V4 生成结果与 V3 生成结果并行对比。
- 第四阶段：确认稳定后，再考虑切换正式流程。

## 5. 风险提示

- 不要一次性替换 `excel_generator.py`。
- 不要一次性重构 `index.html`。
- 不要把实验规则直接覆盖正式模板映射。
- 不要改变现有 V3 API 路径。
- 不要让 V4 实验失败影响正式订单生成。
